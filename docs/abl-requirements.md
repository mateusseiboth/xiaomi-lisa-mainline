# What the stock Xiaomi ABL needs to boot a mainline kernel

Device: Xiaomi 11 Lite 5G NE (`lisa`, SM7325), stock bootloader from
HyperOS 2 (`OS2.0.8.0.UKOMIXM`). The ABL is Qualcomm's edk2 LinuxLoader with
Xiaomi changes. Everything below was found by reading the ABL's own logs (see
[debugging.md](debugging.md)), not by guessing.

The ABL rejects a DTB silently: the phone shows the Xiaomi logo for a moment
and drops back to fastboot. A working mainline boot needs all of this:

## 1. Boot image layout

- `boot.img` header v3 with the kernel (gzip `Image` is fine, the ABL
  decompresses it in ~330 ms).
- `vendor_boot.img` header v3 with the ramdisk, the cmdline and the DTB.
- **Load addresses must match the stock `vendor_boot`**: base `0x0`, kernel
  `0x8000`, ramdisk `0x01000000`, tags `0x100`, DTB `0x01f00000`.
  mkbootimg defaults to base `0x10000000`, which the ABL refuses.
  boot-deploy ignores `deviceinfo_flash_offset_*` for header v3, so they are
  passed through `deviceinfo_bootimg_custom_args`.
- `fastboot boot` (RAM boot) does not work with header v3 on this ABL: the
  staged `vendor_boot` is ignored. Flash `boot` and `vendor_boot`.

## 2. DTB selection

- `qcom,msm-id = <475 0x10000>, <515 0x10000>` (SM7325, as in the stock yupik
  DTB) and `qcom,board-id = <0x1000b 0>` (the stock `lisa` dtbo entry).

## 3. Nodes the ABL edits before handing over

The ABL patches the DTB and aborts if these are missing:

- `/reserved-memory/splash_region` with `reg = <0 0xe1000000 0 0x2300000>`.
  The path and the size are checked
  (`ERROR: Could not get splash memory region node`).
- `/mem-offline` (`compatible = "qcom,mem-offline"`).
- `/firmware/android/fstab`.

## 4. Overlays: dtbo and the Gunyah hypervisor

Even in normal ("Mission") mode the ABL applies overlays with libufdt:

- the board entry from the `dtbo` partition, and
- an overlay generated by the Gunyah ("Haven") hypervisor, which adds
  `/hypervisor`, disables `&wdog` and sets `always-on` on `&arch_timer`.

libufdt resolves those `__fixups__` against the main DTB's `__symbols__`, and
the target nodes need a `phandle`. A mainline DTB has neither, so the result is
`ApplyOverlay: ufdt apply overlay failed` / `Error: Dtb overlay failed`.

The fix:

- build the DTB with `dtc -@` (`DTC_FLAGS_sm7325-xiaomi-lisa := -@`), which
  emits `__symbols__` and a phandle for every labelled node;
- add the labels the hypervisor expects: `wdog` on the watchdog,
  `arch_timer` on `/timer` (`soc` already exists);
- flash a `dtbo` with one entry in the stock format (target by label through
  `__fixups__`) that does nothing. See
  [`dtbo-overlay.dts`](../pmaports/device/testing/device-xiaomi-lisa/dtbo-overlay.dts).
  An erased dtbo fails (`DtboImgBuffer is NULL`), and so does an overlay
  without fragments or one using only `target-path`.

`tools/check-dtb-overlays.sh` applies a simulated hypervisor overlay and the
dtbo overlay with the upstream libufdt, so a DTB can be checked on the PC
before flashing.

## 5. vbmeta

Flash a vbmeta with verification disabled (`pmbootstrap flasher flash_vbmeta`).
The unlocked ABL already skips verification (`Device is unlocked, Skipping boot
verification`), so this is a safety net rather than a requirement.

## Traps

- **Recovery mode sticks.** When the stock Android bootloops it requests a
  recovery boot (reboot reason 34 and/or the misc BCB). From then on the ABL
  boots in recovery mode, which always applies the dtbo overlay. Clear the
  first 2 KiB of `misc` and reboot from Linux to get back to normal mode.
- **Fastboot download buffer.** After a rejected boot, or when entered through
  `reboot bootloader`, fastboot often refuses transfers with
  `Requested download size is more than max allowed`, even for small images,
  and sometimes stops answering. Entering fastboot with Power + Volume down
  works every time. `fastboot -S 256M` helps with large images.
- **Boot logo.** The Xiaomi logo and the unlocked padlock come from
  `imagefv`, which is signed by Xiaomi. Editing it breaks the signature and the
  XBL refuses it. The `splash` partition is not used by this bootloader.
